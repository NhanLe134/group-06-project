## Summary
Sau khi khách bấm "Xác nhận" gửi bếp, đơn được `POST /orders` thành công (HTTP 200, phiếu sinh trong DB) nhưng popup "Đã gửi đơn xuống bếp thành công!" **không bao giờ hiển thị** — màn hình đứng yên như thể bấm không ăn. Nếu demo/giới thiệu US-01 sẽ nhìn như tính năng hỏng.

## Environment
- FE: `frontend/fe_ofc/assets/js/GuiBep.js` (hàm `sendToKitchen`), trang `customer.html`
- Tái hiện trên cả E2E local (backend SQLite tạm, Playwright) lẫn staging

## Reproduction Steps
1. Mở E-Menu một bàn hợp lệ, thêm 1 món vào Order Draft.
2. Bấm "Xác nhận gửi bếp" → modal xác nhận hiện.
3. Bấm "Xác nhận" trong modal.
4. Quan sát: không có popup thành công nào xuất hiện (chờ 5 giây+).

## Expected vs Actual
- **Expected:** Popup `#success-modal` hiện ngay, có dòng "Mã đơn: {phieuban_id}" (US-01 AC4); Draft làm trống.
- **Actual:** POST `/orders` trả 200 (đơn ĐÃ tạo trong DB) nhưng popup không hiện; console có `ReferenceError: res is not defined`.

## Root Cause Analysis
Thêm tính năng "hiển thị mã đơn" (US-01 AC4) khi này: biến `const res = await apiFetch(...)` được khai báo **bên trong khối `try {}`**, nhưng dòng dùng nó — `setText('#success-code', res?.phieuban_id ...)` — nằm **ngoài `try`**, ở scope function. JavaScript `const` có block scope → sau khi `try` kết thúc, `res` không tồn tại → `ReferenceError` ném ra ngay sau khi POST thành công, cắt ngang trước lệnh mở `#success-modal`. Lỗi này unit test thuần không bắt được (chỉ test logic), phải E2E chạy cả trang mới thấy.

## Solution
Dời khai báo ra trước khối `try`:
```js
let res = null; /* khai báo ngoài try — dùng ở popup thành công bên dưới */
try {
  res = await apiFetch('/orders', { ... });
} catch (e) { ... }
// ...setText('#success-code', res?.phieuban_id ? ...)
```
Bổ sung thêm element `#success-code` vào `customer.html` (m Modal thành công bị mất element này khi refactor module) + style `.success-code`.

## Regression Risk
Thấp — thay đổi chỉ scope biến. Rủi ro duy nhất: ai đó thêm `return` trong `catch` quên gán `res = null` → popup hiện dữ liệu cũ; đã né bằng cách khởi tạo `null` và dùng optional chaining.
