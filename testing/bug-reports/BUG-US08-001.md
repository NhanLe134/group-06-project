## Summary
Phiếu kiểm kê lấy A = `soluongton` lúc tạo phiếu. Khi gửi bếp bắt đầu trừ `soluongton`, số đã bán trong kỳ bị trừ một lần ở A và một lần nữa ở C = A − B.

## Environment
Backend `services/inventory.py`, SQLite test / Supabase.

## Reproduction Steps
1. Trà đá tồn 10.
2. Gửi bếp 3 Trà đá (→ `soluongton = 7`).
3. Tạo phiếu kiểm kê.

## Expected vs Actual
- Expected: A = 10, B = 3, C = 7.
- Actual: A = 7, B = 3, C = 4 → đếm thực tế 7 bị báo "dư 3".

## Root Cause Analysis
Giả định cũ trong spec US-08: "chưa có luồng tự trừ `soluongton`". Khi có trừ kho, A phải là tồn **đầu kỳ**.

## Solution
A = `soluongton` lúc tạo phiếu + số đã bán từ đầu kỳ đến lúc tạo phiếu. Cập nhật spec US-08 Mục 2.

## Regression Risk
Hàng nhập thêm giữa ca (sửa `soluongton`) vẫn được tính vào A — đúng theo spec.
