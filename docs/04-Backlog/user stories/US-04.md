## [US-04] - Phục vụ bưng món và Cập nhật trạng thái

As a Nhân viên phục vụ (Waiter), I want nhận thông báo tức thì khi Bếp báo hoàn thành món và thao tác xác nhận đã phục vụ trên thiết bị, so that tôi bưng món ra bàn kịp thời (tránh món bị nguội), cập nhật chính xác sơ đồ bàn (Table Map) và minh bạch trong việc xử lý hủy/đổi món.

Context:
- `REQ-06` (FR): Table Session Map hiển thị màu sắc trạng thái bàn real-time (Xanh: Trống, Đỏ: Đang ăn, Vàng: Cần dọn).
- `REQ-07` (FR): App phục vụ phát âm thanh "Ting Ting" và popup notification khi KDS báo món chín.
- `REQ-10` / `BR-02`: Quyền hạn hủy món (Void/Refund) - Mọi thao tác hủy món bắt buộc phải xác thực bằng mã PIN của Manager. Phục vụ không được phép tự phê duyệt.
- `NFR-RO-03`: Role-Based Access Control (RBAC) - Thiết lập chặt quyền hạn, chặn mọi API gọi trái phép (trả lỗi 403).
- `NFR-RO-04`: Hoạt động ổn định trên thiết bị Tablet/POS Android.
- **AI Integration (Under the hood):** Ứng dụng AI phân tích logic ẩn bên dưới (Backend) để gộp thông báo (AI Smart Batching) và gợi ý bán chéo (AI Upsell). Tái sử dụng hoàn toàn UI Popup/Notification có sẵn, không làm thay đổi layout hay thêm component mới.

Acceptance Criteria:

AC1 (Happy Path - Nhận thông báo món chín & AI Smart Batching)
Given Bếp trưởng hoàn thành 3 món của Bàn 06 và bấm "Done" liên tiếp trên KDS,
When hệ thống đẩy sự kiện qua kênh WebSocket `table:{table_session_id}`, thuật toán AI tự động đánh giá các món này thuộc cùng 1 bàn và ra đồ cùng lúc,
Then Tablet của Waiter phát âm thanh "Ting Ting" một lần và gom nhóm 3 món thành 1 Popup duy nhất (dùng chung UI popup cũ): "Bàn 06: 3 món đã sẵn sàng" để Waiter bưng 1 lần (Batch Serving) thay vì bị spam 3 thông báo liên tục.

AC2 (Happy Path - Xác nhận phục vụ & Table Map Update)
Given Waiter đã mang món ra bàn 06 thành công,
When Waiter bấm "Đã phục vụ" trên thẻ món,
Then trạng thái món chuyển thành `served`, popup thông báo ẩn đi, và Table Map hiển thị bàn 06 chuyển sang màu Đỏ (`occupied`).

AC3 (Advanced Feature - AI Upsell Suggestion qua UI Notification)
Given Bàn 06 đã nhận món chính được 45 phút và trạng thái bàn đang là `occupied`,
When thuật toán AI dự đoán bàn sắp dùng xong bữa dựa trên dữ liệu lịch sử,
Then hệ thống đẩy một Push Notification tiêu chuẩn xuống Tablet Waiter: "Bàn 06 có thể đã ăn xong bữa chính. Khuyến nghị mời thêm Tráng miệng/Nước uống." (Không cần vẽ thêm UI, dùng luôn UI Toast/Notification hiện có).

AC4 (Business Rule - Explicit Authentication khi Hủy món theo BR-02)
Given Khách yêu cầu hủy món (món đang ở trạng thái `cooking`),
When Waiter bấm "Hủy món" trên Tablet,
Then hệ thống chặn thao tác, hiển thị Modal yêu cầu (1) Chọn lý do, (2) Nhập mã PIN Quản lý. Nếu đúng PIN, gọi API `POST /orders/items/void`, status chuyển thành `void` và bắt buộc ghi log vào `void_refund_logs` (`NFR-RO-03`).

AC5 (Fallback / Error Handling - Chế độ Offline Cache)
Given Waiter đi ra góc khuất mất sóng Wi-Fi và bấm "Đã phục vụ",
When API ném lỗi timeout hoặc network error,
Then hệ thống hiển thị Toast "Đang ngoại tuyến, thao tác đã lưu tạm", đưa trạng thái vào Local Storage/IndexedDB và tự động đồng bộ chìm (Background Sync) lên Server ngay khi có mạng lại.

Out of Scope:
- Hỗ trợ định vị vị trí của Waiter qua GPS/Bluetooth trong nhà hàng.

Dependencies:
- Kênh WebSocket realtime (`kds:tickets` và `table:{table_session_id}`).
- Backend AI Engine cho tính năng Batching và Upsell.
- API `POST /orders/items/{id}/void` (Yêu cầu `pin_code`).
- Storage cho Offline Cache (Redux Persist/IndexedDB).

Estimate: 3 points
